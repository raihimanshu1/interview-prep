# 1. What Is Big-O?

Big-O describes:

> How the execution time grows as input size increases.

Example:

Suppose:

```java
int[] arr = new int[100000];
```

Finding an element.

---

## Linear Search

```java
for(int i=0;i<arr.length;i++){

    if(arr[i]==target)
        return i;

}
```

Worst case:

Need to check all elements.

```
100000 elements

↓

100000 comparisons
```

Complexity:

```
O(n)
```

---

## Direct Access

Array:

```java
arr[500]
```

Computer knows memory location directly.

Complexity:

```
O(1)
```

# 17. Java 8 HashMap Improvement ⭐⭐⭐⭐⭐

Java 8 introduced:

```
Treeification
```

When collision becomes large:

Linked list converts into:

```
Red Black Tree


        B

      /   \

     A     C

```

---

Threshold:

```
TREEIFY_THRESHOLD = 8
```

Meaning:

If bucket size crosses 8:

```
LinkedList

      |

      v

Red Black Tree

```

---

Search:

Linked List:

```
O(n)
```

Tree:

```
O(log n)
```

---

# 18. HashMap Complete Complexity Answer ⭐⭐⭐⭐⭐

Interview answer:

> HashMap provides O(1) average time complexity for get and put operations because it uses hashing for direct bucket access. However, in the worst case due to hash collisions, complexity becomes O(n). In Java 8+, when collisions exceed a threshold, the bucket is converted into a Red Black Tree, improving worst-case complexity to O(log n).

This is the answer expected from a senior developer.

# 24. Interview Trap Questions ⭐⭐⭐⭐⭐

## Q1. Is HashMap always O(1)?

Wrong:

> Yes.

Correct:

> Average O(1), worst O(n), Java 8+ worst O(log n) due to treeified buckets.

---

## Q2. Why ArrayList add is O(1)?

Because adding at the end does not require shifting. Resize is occasional, so amortized complexity is O(1).

---

## Q3. Why LinkedList get is slow?

Because it has no index-based access. It must traverse nodes.

---

## Q4. Why TreeMap is O(log n)?

Because it uses a balanced Red Black Tree.
